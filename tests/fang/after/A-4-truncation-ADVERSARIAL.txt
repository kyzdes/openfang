Side observations on the same body:
* The truncated tail is raw file content, and these files contain their own markdown
  headings: every affected agent's prompt ends the section with e.g.
  "## Every Heartbeat\n- [ ] Check for pending tasks..." followed by "..." and then
  </workspace_context>. The patch's pinning test
  test_only_instruction_prose_keeps_markdown_headings asserts that the prompt contains
  exactly 5 `## ` lines, but its fixture's workspace_context ("- Project: openfang
  (Rust)\n<file name=\"SOUL.md\">\nBe nice\n</file>") and its heartbeat_md ("- Check the
  inbox every hour.") carry no headings. On real data (AGENTS.md, HEARTBEAT.md) the
  built prompt has more `## ` lines than the test pins, so the "accepted risk" is
  pinned only against synthetic input.
* data_section() interpolates without escaping, and workspace files are agent-writable.
  A file containing the literal text "</workspace_context>" or "</file>" forges a
  section boundary in the next turn's system prompt. That was possible with `## `
  headings too, but a closing XML-ish tag is a stronger structural signal to the model
  — and the truncation above already makes malformed tags the normal case for 11 of 14
  agents.
