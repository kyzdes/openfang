ROOT CAUSE (crates/openfang-kernel/src/kernel.rs:5729-5733, resolve_driver):
    base_url: fb
        .base_url
        .clone()
        .or_else(|| dm.base_url.clone())            // <-- default_model wins
        .or_else(|| self.lookup_provider_url(&fb_provider)),

  [provider_urls] IS in the chain, but third. dm.base_url takes the slot first,
  so the lookup is only ever reached when [default_model] has no base_url at all.

  The primary model does the opposite and documents the intent
  (kernel.rs:5619-5630): "Don't inherit default provider's base_url when
  switching providers" -- it consults lookup_provider_url() directly whenever
  agent_provider != default_provider.

  The global [[fallback_providers]] chain also does it correctly
  (kernel.rs:5771-5774): fb.base_url.or_else(|| lookup_provider_url(&fb.provider)).

  So only the per-agent manifest fallback is wrong, and it is wrong in a
  data-dependent way: harmless when the fallback provider happens to equal
  [default_model].provider (proved by test-a7-inherit-hf passing), fatal when it
  differs (test-a7-inherit).

SECOND, SEPARATE SITE OF THE SAME DEFECT (not exercised by this script):
  crates/openfang-runtime/src/agent_loop.rs:1269 (complete_with_retry) and
  crates/openfang-runtime/src/agent_loop.rs:1449 (stream_with_retry), the
  ModelNotFound fallback chain (#845), build their driver with
        base_url: fb.base_url.clone(),
  and nothing else -- no dm.base_url, no lookup_provider_url. A fallback without
  an explicit base_url therefore reaches create_driver with base_url = None; for a
  custom provider such as y7router that is not in provider_defaults(), that path
  ends in drivers/mod.rs:568-583 with
        "Provider 'y7router' has API key (Y7ROUTER_API_KEY is set) but no base_url
         configured."
  and the fallback is skipped entirely. This branch only runs when the primary
  error classifies as ModelNotFound, which a dead base_url does not produce, so
  this script cannot reach it. A patch that fixes only kernel.rs leaves it standing.
  Those two sites also read the key with std::env::var directly, bypassing
  resolve_credential (vault -> dotenv -> env), which is a further divergence.

PATCH TARGET:
  1. kernel.rs:5729-5733 -- drop the .or_else(|| dm.base_url.clone()) step, or
     gate it on fb_provider == dm.provider, mirroring the primary at 5619-5630.
  2. agent_loop.rs:1269 and :1449 -- these have no access to the kernel config;
     either resolve the URL before the call and pass it in, or make FallbackModel
     carry a resolved base_url populated once in the kernel.
